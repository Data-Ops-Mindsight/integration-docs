Integration Guide: Job Postings and Hired Applicants

A practical guide to integrate your system with the Mindsight Recruitment ATS: authenticate with a key pair, list and create job postings, read the expandable fields (such as the job requisition) and fetch hired applicants. Everything was validated with real calls.

Overview

The Mindsight Recruitment ATS external API lets your system read users and job postings, create new job postings, and fetch the hired applicants of each one.

ⓘ
This page is different from the MindMatch guide

MindMatch uses the app.mindsight.com.br host and an event journal. The ATS API described here uses the recrutamento.mindsight.com.br host, is per tenant (each company has its own prefix) and has its own set of endpoints. Both use the same kind of authentication (JWT-bearer), but with a different client_id, aud and token URL.

Base URL

Base URL 
https://recrutamento.mindsight.com.br/{tenant}/external-api/v1/

Replace {tenant} with your company's prefix (provided by Mindsight). The trailing slash (/) is mandatory: without it the server does not return JSON (see Observed behaviors).

1. Generate your key pair

You sign the authentication requests with the private key; Mindsight verifies them with the public key, which you send in advance. In return you receive a client_id (UUID4), for example 60955d10-6c30-4e73-bb2c-c9878b59007d.

Shell (OpenSSL) 
openssl genrsa -out private.pem 2048
openssl rsa -in private.pem -outform PEM -pubout -out public.pem
⚠
Send the public key, keep the private one

Only public.pem goes to Mindsight. private.pem never leaves your environment and must not be committed to git.

2. Authenticate

The flow is OAuth 2.0 with Private Key JWT (RFC 7523): you build a JWT called client_assertion, sign it with your private key (RS256) and exchange it for an access token.

1. Build the client_assertion

Header 
{
  "alg": "RS256",
  "typ": "JWT"
}
Body (claims) 
{
  "iss": "YOUR_CLIENT_ID",
  "sub": "YOUR_CLIENT_ID",
  "aud": "https://recrutamento.mindsight.com.br/",
  "iat": 1758000000,
  "exp": 1758003600,
  "jti": "92ceb8f8-0ff7-479b-833e-87d99fc53185"
}
ClaimValue
iss and subYour client_id.
audFixed: https://recrutamento.mindsight.com.br/ (without the tenant).
jtiA new UUID4 for every assertion, used only once.
iatNow, in Unix epoch. It cannot be more than 5 minutes in the past.
expiat + 3600. It cannot be more than 60 minutes ahead of the server clock, nor in the past.

2. Exchange it for an access token

POST https://recrutamento.mindsight.com.br/{tenant}/external-api/v1/oauth/token/
application/x-www-form-urlencoded 
grant_type=urn:ietf:params:oauth:grant-type:jwt-bearer
client_assertion_type=urn:ietf:params:oauth:client-assertion-type:jwt-bearer
client_assertion=<the signed JWT from step 1>
200 response 
{
  "token_type": "Bearer",
  "access_token": "eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...",
  "expires_in": 3600
}

Python example

Python 
import time
from uuid import uuid4

import jwt  # pip install PyJWT cryptography
import requests

TENANT = "your-tenant"
CLIENT_ID = "YOUR_CLIENT_ID"
API_BASE = f"https://recrutamento.mindsight.com.br/{TENANT}/external-api/v1/"
PRIVATE_KEY_PEM = open("private.pem").read()  # in production, load from a secrets manager


def build_client_assertion() -> str:
    now = int(time.time())
    claims = {
        "iss": CLIENT_ID,
        "sub": CLIENT_ID,
        "aud": "https://recrutamento.mindsight.com.br/",
        "iat": now,
        "exp": now + 3600,
        "jti": str(uuid4()),
    }
    return jwt.encode(claims, PRIVATE_KEY_PEM, algorithm="RS256", headers={"alg": "RS256", "typ": "JWT"})


def get_access_token() -> str:
    response = requests.post(
        f"{API_BASE}oauth/token/",
        data={
            "grant_type": "urn:ietf:params:oauth:grant-type:jwt-bearer",
            "client_assertion_type": "urn:ietf:params:oauth:client-assertion-type:jwt-bearer",
            "client_assertion": build_client_assertion(),
        },
        timeout=30,
    )
    response.raise_for_status()
    return response.json()["access_token"]


session = requests.Session()
session.headers["Authorization"] = f"Bearer {get_access_token()}"

Token endpoint errors

Every problem with the JWT (expired, old iat, distant exp, wrong aud, invalid signature, arbitrary text) returns the same error, with no detail. To debug, check your machine clock, aud, client_id and whether the private key matches the public key you sent.

SituationStatusBody
Any problem with client_assertion or client_assertion_type400{"error": "invalid_client"}
grant_type different from the expected one400{"error": "unsupported_grant_type"}
URL without the trailing slash (oauth/token)403HTML error page (not JSON)

Revoke a token

Optional. Revokes the token in use or another token of yours. Once revoked, the token answers 401.

POST https://recrutamento.mindsight.com.br/{tenant}/external-api/v1/oauth/revoke/
application/x-www-form-urlencoded 
token=<access_token>
token_type_hint=access_token   # optional

Returns 200 with body {}.

Server public key

Returns the server's public key in JWK format (kty, alg, use, n, e), useful to validate the signature of the issued access tokens. It does not require authentication.

GET https://recrutamento.mindsight.com.br/{tenant}/external-api/v1/oauth/server-public-key/
ⓘ
The token lasts 1 hour

There is no refresh token: when it expires, build a new client_assertion (with a new jti) and request another access token. The simplest pattern is one token per run of your routine.

4. List job postings

Returns the tenant's job postings, from newest to oldest. It is also the only way to read a specific job posting.

GET https://recrutamento.mindsight.com.br/{tenant}/external-api/v1/job-postings/

Query parameters

ParameterValuesEffect
searchtext or numberSearches id and name. ?search=129 returns only job posting 129.
statusIN_PROGRESS, CANCELED, SUSPENDED, FINALIZEDFilters by status. An invalid value returns 400.

Without expand, the field simply does not exist

Without ?expand=request the request key is not even in the response. An unknown name in expand (e.g. ?expand=foo) is ignored without an error, so a typo goes unnoticed: check that the expected key came back.

⚠
Unknown fields are silently ignored

Sending work_model, hire_model or status on creation returns 201, but those values are not applied (the job posting keeps null work_model/hire_model and IN_PROGRESS). Use only the five fields in the table.

ⓘ
There is no way to edit or delete through the API

This external API only creates and reads job postings. To fix or remove a job posting created by mistake, use the platform. In a test environment, prefix the names (e.g. TEST-) so you can find them later with ?search=.

Additional fields on request

Upon request to Mindsight support, the endpoint also returns cpf, rg, gender (MALE, FEMALE, OTHER) and marital_status (SINGLE, MARRIED, DIVORCED, WIDOW, CONCUBINAGE, SEPARATED, STABLE_UNION, OTHER). These fields did not appear in the test tenant, where the option is not enabled.

⚠
Applicants who give up disappear from the list

Applicants can give up during the Hired stage. A call made before they gave up included them; later calls do not. If you store the hired applicants in your system, compare on every sync and treat a disappearance as an exit.

A job posting with no hired applicants returns 200 with count: 0. A non-existent job posting returns 404 with {"message": "Vaga não encontrada."}.

9. Complete Python recipe

A lean client that reuses the get_access_token() from step 2, walks every page and reads a job posting with its expanded fields.

Python 
def paginate(session, path, **params):
    # Walks every page and yields all the items.
    url = f"{API_BASE}{path}"
    while url:
        response = session.get(url, params=params, timeout=30)
        response.raise_for_status()
        if "application/json" not in response.headers.get("Content-Type", ""):
            raise RuntimeError(f"Response is not JSON: check the trailing slash in {url}")
        payload = response.json()
        yield from payload["results"]
        url, params = payload["next"], {}  # next already carries the parameters


def get_job_posting(session, job_id, expand="request"):
    # There is no GET /job-postings/{id}/, so we use the search by id.
    for job in paginate(session, "job-postings/", search=job_id, expand=expand):
        if job["id"] == job_id:
            return job
    return None


def create_job_posting(session, name, positions, **optional):
    # optional accepts description, manager_id and recruiter_id.
    response = session.post(
        f"{API_BASE}job-postings/",
        json={"name": name, "positions": positions, **optional},
        timeout=30,
    )
    if response.status_code == 400:
        raise ValueError(response.json())
    response.raise_for_status()
    return response.json()["id"]


# Reads the job requisition of job posting 129
job = get_job_posting(session, 129, expand="request,description,candidates_count")
print(job["request"]["claimant_commentary"])

# All in-progress job postings, with candidate counters
in_progress = list(paginate(session, "job-postings/", status="IN_PROGRESS", expand="candidates_count"))

# Hired applicants of a job posting
hired = list(paginate(session, "job-postings/122/hired-applicants/"))

10. Security and operations

⚠
Never expose your private key

Keep it in a secrets manager or environment variable. Never in a git repository, a shared notebook, browser JavaScript or logs.

Good practices

  • One token per run of your routine; re-authenticate at the start instead of keeping tokens between runs.
  • Revoke the token when you finish, if your policy requires it (oauth/revoke/).
  • Applicant data (email, phone, and CPF/RG when enabled) is personal data: apply data protection rules (LGPD) when storing it.
  • Handle off-pattern responses: check Content-Type and the status before reading the JSON.

Rotating the key pair

If the private key is compromised, generate a new pair and send the new public key to Mindsight support, who will update your client_id.

Next steps

With authentication working, start with users/ and job-postings/ to validate access and then create your first job posting.
