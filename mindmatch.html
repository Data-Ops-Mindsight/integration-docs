Client Integration Guide

A step-by-step guide for an ATS vendor connecting to MindMatch for the first time: generating your key pair, authenticating, reading the data, and keeping it in sync continuously. MindMatch uses its own JWT-bearer authentication — separate from the OAuth client_credentials flow used by Mindsight's other APIs.

Overview

This page is for an ATS integrating with MindMatch directly — reading candidate scores and match results as they're produced, so your own platform can act on them.

ⓘ
There is no bulk/historical import step

MindMatch's event journal keeps roughly 6 months of history. A new integration doesn't need a separate one-time export — you start directly on the continuous recurring sync described in Recurrence, with your first start_datetime set to your go-live date (or up to ~6 months back if you need that history).

At a glance, the path from zero to a running integration:

01 Generate a key pair

Create an RSA key pair and send Mindsight the public half.

02 Authenticate

Sign a short-lived JWT and exchange it for an access token.

03 Sync continuously

Poll the event journal on a watermark, not a one-off export.

1. Generate your key pair

MindMatch authenticates your application with an RSA key pair instead of a shared secret: you sign requests with your private key, and Mindsight verifies them with the public key you send them up front.

01 Generate the pair

2048-bit RSA, locally — the private key never leaves your side.

02 Send the public key

Share public.pem with Mindsight support to get a client_id.

03 Store the private key

In a secrets manager or environment variable — never in git.

Command line

Shell 
openssl genrsa -out private.pem 2048
openssl rsa -in private.pem -pubout -out public.pem

Python equivalent

Python 
from cryptography.hazmat.primitives import serialization
from cryptography.hazmat.primitives.asymmetric import rsa

private_key = rsa.generate_private_key(public_exponent=65537, key_size=2048)

private_pem = private_key.private_bytes(
    encoding=serialization.Encoding.PEM,
    format=serialization.PrivateFormat.PKCS8,
    encryption_algorithm=serialization.NoEncryption(),
)
public_pem = private_key.public_key().public_bytes(
    encoding=serialization.Encoding.PEM,
    format=serialization.PublicFormat.SubjectPublicKeyInfo,
)

with open("private.pem", "wb") as f:
    f.write(private_pem)
with open("public.pem", "wb") as f:
    f.write(public_pem)
⚠
Send the public key, keep the private key

Only public.pem goes to Mindsight. Mindsight sends back a CLIENT_ID that identifies your application — you'll use it together with your private key in every authentication request.

2. Authenticate

MindMatch uses the OAuth 2.0 JWT-bearer grant (RFC 7523): you sign a short-lived JWT with your private key to prove who you are, and exchange it for an access token.

1. Build the signed assertion (RS256)

The JWT claims identify your application and expire quickly:

JWT claims 
{
  "iss": "YOUR_CLIENT_ID",
  "sub": "YOUR_CLIENT_ID",
  "aud": "https://app.mindsight.com.br/",
  "iat": 1758000000,
  "exp": 1758003600,
  "jti": "a3f1c2e4-9b7d-4e21-8c6a-7f2d5b9e1a40"
}

2. Exchange it for an access token

POST https://app.mindsight.com.br/api/v2/oauth/token/
application/x-www-form-urlencoded 
grant_type=urn:ietf:params:oauth:grant-type:jwt-bearer
client_assertion_type=urn:ietf:params:oauth:client-assertion-type:jwt-bearer
client_assertion=<the signed JWT from step 1>

Python example

Python 
import time
from uuid import uuid4

import jwt
import requests
from cryptography.hazmat.primitives import serialization

API_BASE = "https://app.mindsight.com.br/api/v2/"
CLIENT_ID = "YOUR_CLIENT_ID"
PRIVATE_KEY_PEM = open("private.pem").read()  # load from a secret manager in production


def build_client_assertion() -> str:
    private_key = serialization.load_pem_private_key(PRIVATE_KEY_PEM.encode(), password=None)
    pem = private_key.private_bytes(
        encoding=serialization.Encoding.PEM,
        format=serialization.PrivateFormat.PKCS8,
        encryption_algorithm=serialization.NoEncryption(),
    ).decode()

    now = int(time.time())
    claims = {
        "iss": CLIENT_ID,
        "sub": CLIENT_ID,
        "aud": "https://app.mindsight.com.br/",
        "iat": now,
        "exp": now + 3600,
        "jti": str(uuid4()),
    }
    return jwt.encode(claims, pem, algorithm="RS256", headers={"alg": "RS256", "typ": "JWT"})


def get_access_token() -> str:
    response = requests.post(
        f"{API_BASE}oauth/token/",
        data={
            "grant_type": "urn:ietf:params:oauth:grant-type:jwt-bearer",
            "client_assertion_type": "urn:ietf:params:oauth:client-assertion-type:jwt-bearer",
            "client_assertion": build_client_assertion(),
        },
        timeout=30,
    )
    response.raise_for_status()
    return response.json()["access_token"]


access_token = get_access_token()
ⓘ
The token is valid for 1 hour

Don't try to refresh a token in place — just build a new client assertion and request a new access token. The simplest pattern is one token per sync run (see Recurrence).

3. List functions (archetypes)

Every candidate is matched against one or more "functions" (archetypes). Fetch the list once per run so you can resolve function_id to a name.

GET https://app.mindsight.com.br/api/v2/ats-integration/functions

The response is paginated (results + next):

Python 
def list_functions(session: requests.Session) -> dict[int, str]:
    functions: dict[int, str] = {}
    url = f"{API_BASE}ats-integration/functions"
    while url:
        payload = session.get(url, timeout=30).json()
        for item in payload.get("results", []):
            functions[int(item["id"])] = item["name"]
        url = payload.get("next")
    return functions


session = requests.Session()
session.headers["Authorization"] = f"Bearer {access_token}"
functions = list_functions(session)

4. Read the event journal

This is the endpoint you'll poll continuously: it returns every event created since a given timestamp — new candidates, updated scores, deleted scores, match results.

GET …/ats-integration/event-journal?start_datetime=2026-09-18T00:00:00Z

The response is a plain list (no pagination) of every event since start_datetime, in UTC, ISO 8601:

Python 
from datetime import datetime, timezone


def fetch_events(session: requests.Session, start: datetime) -> list[dict]:
    start_utc = start.astimezone(timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ")
    response = session.get(
        f"{API_BASE}ats-integration/event-journal",
        params={"start_datetime": start_utc},
        timeout=600,  # a wide window (e.g. 6 months) can take a couple of minutes
    )
    response.raise_for_status()
    return response.json()
ⓘ
Retention is ~6 months

Don't rely on the journal for anything older than that. If you ever need history beyond 6 months, ask Mindsight support for an export — it's not something this endpoint can give you.

6. Build continuous recurrence

There's no "initial load" endpoint — your integration is one recurring job from day one. The pattern is a watermark: remember where your last successful run left off, and start the next run a little before that point.

01 Watermark

Store the end time of your last successful run.

02 Small overlap

Start the next run a few minutes before the watermark, not hours.

03 Idempotent writes

Re-seeing an event is safe — upsert by person_id/event id.

If a run fails, don't move the watermark — the next run will simply retry the same window. Reprocessing overlap is intentional and safe as long as your own writes are idempotent.

Python 
import time
from datetime import datetime, timedelta, timezone

OVERLAP = timedelta(minutes=5)  # small safety margin anchored on the watermark
POLL_EVERY = 15 * 60  # seconds


def run_once(watermark: datetime) -> datetime:
    started_at = datetime.now(timezone.utc)
    window_start = watermark - OVERLAP

    session = requests.Session()
    session.headers["Authorization"] = f"Bearer {get_access_token()}"
    functions = list_functions(session)
    events = fetch_events(session, window_start)

    # apply(events, functions) -> write to your own store, keyed by event id
    # so reprocessing the overlap never double-applies anything.

    return started_at  # new watermark — only advance it after a successful run


watermark = datetime(2026, 9, 1, tzinfo=timezone.utc)  # first run: your go-live date
while True:
    try:
        watermark = run_once(watermark)
    except Exception:
        pass  # keep the old watermark; the next run retries this same window
    time.sleep(POLL_EVERY)
ⓘ
Pick a polling interval that matches your use case

A few minutes if you act on scores in near real time (e.g. feeding a decision back into your ATS); hourly or daily is plenty for reporting or analytics use cases. Shorter intervals mean a shorter overlap margin — minutes, not hours.

7. Security & operations

Your private key is the only thing standing between MindMatch and anyone who could impersonate your application.

⚠
Never expose your private key

Keep it in a secrets manager or environment variable — never in a git repository, a notebook, client-side JavaScript, or logs.

Token lifecycle

Access tokens last 1 hour. Re-authenticate at the start of each sync run rather than trying to cache and refresh a token across runs — it's simpler and avoids edge cases around expiry mid-run.

Rotating your key pair

If your private key is ever compromised, generate a new pair (see Key pair) and send Mindsight support the new public key — they'll switch your client_id over to it.
