API MindMatch

Guia de Integração para Clientes

Um guia passo a passo para quem vai integrar o próprio ATS com o MindMatch pela primeira vez: gerar seu par de chaves, autenticar, ler os dados e manter a sincronização contínua. O MindMatch usa sua própria autenticação JWT-bearer — separada do fluxo OAuth client_credentials usado pelas outras APIs da Mindsight.

Visão geral

Esta página é para quem vai integrar o próprio ATS direto com o MindMatch — lendo as notas dos candidatos e os resultados de match conforme são produzidos, para a sua plataforma agir sobre eles.

ⓘ
Não existe etapa de carga em lote/histórica

O event journal do MindMatch guarda aproximadamente 6 meses de histórico. Uma integração nova não precisa de uma exportação única e separada — você já começa direto na sincronização recorrente contínua descrita em Recorrência, com o primeiro start_datetime na sua data de entrada em produção (ou até ~6 meses atrás, se precisar desse histórico).

Resumindo, o caminho do zero até uma integração rodando:

01 Gerar um par de chaves

Criar um par de chaves RSA e enviar a metade pública para a Mindsight.

02 Autenticar

Assinar um JWT de curta duração e trocá-lo por um access token.

03 Sincronizar continuamente

Fazer polling do event journal com base numa marca d'água, não numa exportação única.

1. Gere seu par de chaves

O MindMatch autentica sua aplicação com um par de chaves RSA em vez de um segredo compartilhado: você assina as requisições com sua chave privada, e a Mindsight as verifica com a chave pública que você envia antecipadamente.

01 Gerar o par

RSA de 2048 bits, localmente — a chave privada nunca sai do seu lado.

02 Enviar a chave pública

Compartilhe o public.pem com o suporte da Mindsight para receber um client_id.

03 Guardar a chave privada

Em um gerenciador de segredos ou variável de ambiente — nunca no git.

Linha de comando

Shell 
openssl genrsa -out private.pem 2048
openssl rsa -in private.pem -pubout -out public.pem

Equivalente em Python

Python 
from cryptography.hazmat.primitives import serialization
from cryptography.hazmat.primitives.asymmetric import rsa

private_key = rsa.generate_private_key(public_exponent=65537, key_size=2048)

private_pem = private_key.private_bytes(
    encoding=serialization.Encoding.PEM,
    format=serialization.PrivateFormat.PKCS8,
    encryption_algorithm=serialization.NoEncryption(),
)
public_pem = private_key.public_key().public_bytes(
    encoding=serialization.Encoding.PEM,
    format=serialization.PublicFormat.SubjectPublicKeyInfo,
)

with open("private.pem", "wb") as f:
    f.write(private_pem)
with open("public.pem", "wb") as f:
    f.write(public_pem)
⚠
Envie a chave pública, guarde a privada

Só o public.pem vai para a Mindsight. A Mindsight devolve um CLIENT_ID que identifica sua aplicação — você vai usá-lo junto com sua chave privada em toda requisição de autenticação.

2. Autentique

O MindMatch usa o grant OAuth 2.0 JWT-bearer (RFC 7523): você assina um JWT de curta duração com sua chave privada para provar quem você é, e o troca por um access token.

1. Monte a assertion assinada (RS256)

As claims do JWT identificam sua aplicação e expiram rápido:

Claims do JWT 
{
  "iss": "YOUR_CLIENT_ID",
  "sub": "YOUR_CLIENT_ID",
  "aud": "https://app.mindsight.com.br/",
  "iat": 1758000000,
  "exp": 1758003600,
  "jti": "a3f1c2e4-9b7d-4e21-8c6a-7f2d5b9e1a40"
}

2. Troque por um access token

POST https://app.mindsight.com.br/api/v2/oauth/token/
application/x-www-form-urlencoded 
grant_type=urn:ietf:params:oauth:grant-type:jwt-bearer
client_assertion_type=urn:ietf:params:oauth:client-assertion-type:jwt-bearer
client_assertion=<o JWT assinado do passo 1>

Exemplo em Python

Python 
import time
from uuid import uuid4

import jwt
import requests
from cryptography.hazmat.primitives import serialization

API_BASE = "https://app.mindsight.com.br/api/v2/"
CLIENT_ID = "YOUR_CLIENT_ID"
PRIVATE_KEY_PEM = open("private.pem").read()  # carregue de um gerenciador de segredos em produção


def build_client_assertion() -> str:
    private_key = serialization.load_pem_private_key(PRIVATE_KEY_PEM.encode(), password=None)
    pem = private_key.private_bytes(
        encoding=serialization.Encoding.PEM,
        format=serialization.PrivateFormat.PKCS8,
        encryption_algorithm=serialization.NoEncryption(),
    ).decode()

    now = int(time.time())
    claims = {
        "iss": CLIENT_ID,
        "sub": CLIENT_ID,
        "aud": "https://app.mindsight.com.br/",
        "iat": now,
        "exp": now + 3600,
        "jti": str(uuid4()),
    }
    return jwt.encode(claims, pem, algorithm="RS256", headers={"alg": "RS256", "typ": "JWT"})


def get_access_token() -> str:
    response = requests.post(
        f"{API_BASE}oauth/token/",
        data={
            "grant_type": "urn:ietf:params:oauth:grant-type:jwt-bearer",
            "client_assertion_type": "urn:ietf:params:oauth:client-assertion-type:jwt-bearer",
            "client_assertion": build_client_assertion(),
        },
        timeout=30,
    )
    response.raise_for_status()
    return response.json()["access_token"]


access_token = get_access_token()
ⓘ
O token vale 1 hora

Não tente renovar um token no lugar — apenas monte uma nova client assertion e peça um novo access token. O padrão mais simples é um token por execução de sincronização (veja Recorrência).

3. Liste as funções (arquétipos)

Todo candidato é avaliado contra uma ou mais "funções" (arquétipos) — uma taxonomia fixa do lado da Mindsight. Não confunda com uma opening (sua própria vaga, criada via API do ATS, que só aponta para uma dessas funções — veja Entenda os dados). Busque a lista de funções uma vez por execução para resolver function_id em um nome.

GET https://app.mindsight.com.br/api/v2/ats-integration/functions

A resposta é paginada (results + next):

Python 
def list_functions(session: requests.Session) -> dict[int, str]:
    functions: dict[int, str] = {}
    url = f"{API_BASE}ats-integration/functions"
    while url:
        payload = session.get(url, timeout=30).json()
        for item in payload.get("results", []):
            functions[int(item["id"])] = item["name"]
        url = payload.get("next")
    return functions


session = requests.Session()
session.headers["Authorization"] = f"Bearer {access_token}"
functions = list_functions(session)

4. Leia o event journal

Esse é o endpoint que você vai consultar continuamente: ele devolve todo evento criado desde um timestamp informado — candidatos novos, notas atualizadas, notas apagadas, resultados de match.

GET …/ats-integration/event-journal?start_datetime=2026-09-18T00:00:00Z

A resposta é uma lista simples (sem paginação) de todo evento desde start_datetime, em UTC, ISO 8601:

Python 
from datetime import datetime, timezone


def fetch_events(session: requests.Session, start: datetime) -> list[dict]:
    start_utc = start.astimezone(timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ")
    response = session.get(
        f"{API_BASE}ats-integration/event-journal",
        params={"start_datetime": start_utc},
        timeout=600,  # uma janela larga (ex.: 6 meses) pode levar alguns minutos
    )
    response.raise_for_status()
    return response.json()
ⓘ
A retenção é de ~6 meses

Não conte com o journal pra nada mais antigo que isso. Se precisar de histórico além de 6 meses, peça uma exportação ao suporte da Mindsight — não é algo que esse endpoint entrega.

5. Entenda os dados

Todo evento tem o mesmo envelope: um id, um created_at, e uma message com um type e um payload content. Os exemplos abaixo foram adaptados dos próprios payloads de referência da Mindsight.

ⓘ
external_person_id / external_opening_id são suas chaves de correlação — se você as definir

Quando você cria uma pessoa ou uma opening pela API do ATS, pode passar seu próprio id junto; o MindMatch devolve esse id em todo evento abaixo. Se sua integração não os define, eles simplesmente voltam null — use person_id (estável, sempre presente) ou candidate_uuid/ manager_feedback_page_url como alternativa.

6. Construa a recorrência contínua

Não existe um endpoint de "carga inicial" — sua integração já é um job recorrente desde o primeiro dia. O padrão é uma marca d'água: lembrar onde sua última execução bem-sucedida parou, e começar a próxima execução um pouco antes desse ponto.

01 Marca d'água

Guarde o horário de fim da sua última execução bem-sucedida.

02 Sobreposição pequena

Comece a próxima execução alguns minutos antes da marca d'água, não horas.

03 Escritas idempotentes

Ver um evento de novo é seguro — faça upsert por person_id/id do evento.

Se uma execução falhar, não avance a marca d'água — a próxima execução simplesmente tenta de novo a mesma janela. Reprocessar a sobreposição é intencional e seguro, desde que suas próprias escritas sejam idempotentes.

Python 
import time
from datetime import datetime, timedelta, timezone

OVERLAP = timedelta(minutes=5)  # margem de segurança pequena, ancorada na marca d'água
POLL_EVERY = 15 * 60  # segundos


def run_once(watermark: datetime) -> datetime:
    started_at = datetime.now(timezone.utc)
    window_start = watermark - OVERLAP

    session = requests.Session()
    session.headers["Authorization"] = f"Bearer {get_access_token()}"
    functions = list_functions(session)
    events = fetch_events(session, window_start)

    # apply(events, functions) -> grave no seu próprio armazenamento, indexado
    # pelo id do evento, assim reprocessar a sobreposição nunca aplica nada em duplicidade.

    return started_at  # nova marca d'água — só avance depois de uma execução bem-sucedida


watermark = datetime(2026, 9, 1, tzinfo=timezone.utc)  # primeira execução: sua data de entrada em produção
while True:
    try:
        watermark = run_once(watermark)
    except Exception:
        pass  # mantenha a marca d'água antiga; a próxima execução tenta de novo essa mesma janela
    time.sleep(POLL_EVERY)
ⓘ
Escolha um intervalo de polling que combine com seu caso de uso

Alguns minutos se você age sobre as notas quase em tempo real (ex.: alimentando uma decisão de volta no seu ATS); de hora em hora ou diário é suficiente para relatórios ou análises. Intervalos mais curtos significam uma margem de sobreposição menor — minutos, não horas.

7. Segurança e operação

Sua chave privada é a única coisa que separa o MindMatch de qualquer um que possa se passar pela sua aplicação.

⚠
Nunca exponha sua chave privada

Guarde-a em um gerenciador de segredos ou variável de ambiente — nunca em um repositório git, um notebook, JavaScript do lado do cliente, ou logs.

Ciclo de vida do token

Os access tokens duram 1 hora. Reautentique no início de cada execução de sincronização, em vez de tentar guardar e renovar um token entre execuções — é mais simples e evita casos extremos de expiração no meio de uma execução.

Rotacionando seu par de chaves

Se sua chave privada for comprometida, gere um par novo (veja Par de chaves) e envie a chave pública nova ao suporte da Mindsight — eles vão trocar seu client_id para ela.
